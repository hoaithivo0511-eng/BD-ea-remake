# TIP-505 — Move DrawLevels to the timer

- Priority: P2
- Depends on: TIP-502 (shares BlackDragon.mq5)
- Finding: BD-R8

## Task
`g_panel.DrawLevels(...)` ran at the end of every `OnTick`, against
ARCHITECTURE rule C3 ("UI redraws follow the 500 ms timer"). On a busy
gold feed that is several `ObjectMove`/`ObjectCreate` calls per tick with
no visual benefit. Move the call into `OnTimer`, after the BD-R4 halt
block and before `g_panel.Refresh(...)`. Leave a comment in `OnTick`
explaining where it went.

## Constraints
- Levels themselves stay computed EVERY tick in `g_basket.Update()`;
  only the redraw is throttled.
- No change to `Panel.mqh`.
- `fDraw=false` path unchanged.

## Acceptance
- Lines still appear/track within 500 ms of a level change.
- Tester run produces identical trade list (drawing is cosmetic).
- Visible drop in per-tick object API calls under a profiler / tick storm.
