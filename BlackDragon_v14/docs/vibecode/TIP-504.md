# TIP-504 — Drop vanished tickets from the basket cache

- Priority: P2
- Depends on: (none)
- Finding: BD-R7

## Task
`RefreshFloating()` detected a ticket that no longer exists but only set
`m_dirty`. The rest of that tick — `ComputeLevels`, `Exit_OverlapHit`,
`TryGridAdd` — still ran on a basket whose `count` / `totalLots` included
the dead position, so breakeven, TP/SL and the DCA index were wrong for
one full tick.
Compact survivors in place with a write index `w`; rebuild `count`,
`totalLots`, `totalProfit`, `swapSum` from survivors; `ArrayResize`.
Return whether anything was dropped and run `Update()` as a BOUNDED
2-pass loop (`Rebuild` -> `RefreshFloating` -> break when clean).

## Constraints
- Never more than 2 passes per tick (no unbounded loop on the tick path).
- `ArrayResize` only when something was actually dropped.
- `ComputeSide` early-returns on `count == 0` — keep that path intact.

## Acceptance
- Manual close of one DCA leg -> same tick shows correct basket size,
  breakeven and Overlap decision (previously one tick late).
- No behaviour change when nothing vanishes (the common case).
- Note: the DCA index counts OPEN orders, so it now steps back on the same
  tick instead of the next one. Confirm on a tester A/B before merge.
