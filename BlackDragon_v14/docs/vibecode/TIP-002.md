# TIP-002 — Idempotent async lifecycle

- Priority: P0
- Depends on: TIP-001

## Task

Retain async journal guards until an outcome is observable from deal, order or
position state.

## Constraints

- REQUEST accepted is state advancement, not completion.
- Support event reordering.
- No blocking wait or `Sleep`.
- Keep watchdog recovery and compact inactive entries.

## Acceptance

- Accepted request remains active.
- Rejected request releases.
- Matching observed state completes once.
- Soft timeout does not release unresolved requests.
- Hard timeout is bounded and logged.
