# TIP-501 — Scale Slippage_ by PointScale

- Priority: P1
- Depends on: (none)
- Finding: BD-R2

## Task
`req.deviation = Slippage_` was the only point-based input bypassing
FE-201 scaling (ARCHITECTURE rule 8). Add a PURE `Exec_Deviation(points,
scale)` in ExecutionLayer.mqh and use it at all three send sites:
`OpenMarket`, `ClosePosition` (`Cfg.PointScale`) and `ClosePositionEx`
(`Sym_PointScaleFor(sym)` — FE-401 is cross-symbol).
Add `Sym_IsGoldSym` / `Sym_PointScaleFor` explicit-symbol variants in
GridEngine.mqh; `Sym_IsGold` / `Sym_PointScale` delegate to them.

## Constraints
- No input default changes. No `[STRATEGY-BEHAVIOR]` formula changes.
- Clamp: slippage < 0 -> 0, scale < 1 -> 1. Never widen silently.
- Tester unaffected on 2-digit gold (scale = 1 -> identical requests).

## Acceptance
- 3-digit gold: `Slippage_=3` sends `deviation=30` (0.30 USD), not 3.
- `AutoGoldPip=false` -> scale 1 -> `deviation=3` as before.
- CloseAllAccount on a foreign symbol uses THAT symbol's scale.
- 6 new asserts in RunTests.mq5 + offline_suite.cpp (pure function).
