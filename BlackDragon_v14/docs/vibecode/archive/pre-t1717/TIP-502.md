# TIP-502 — Persist the daily halt deadline

- Priority: P1
- Depends on: (none)
- Finding: BD-R4

## Task
A daily SL/TP halt lived only in `CMoneyGuard::m_haltUntil`, and `Init()`
zeroed it. Any restart / recompile / parameter change on the same day
resumed trading immediately after the daily loss limit fired.
Add `datetime HaltUntil` to `SConfig`; mirror it in `StartHalt`; restore
it in `Init()`; clear it when the halt expires. Extend `SPersistedState`
(magic BD15 -> BD16) with `haltUntil`. Save on TRANSITIONS only, via
`g_lastSavedHalt` in `OnTimer` — never on the 500 ms cadence.
Extract PURE `MG_HaltDeadline(dayStart, delayMin)` with a negative-delay
clamp.

## Constraints
- `Persist_*` stay no-ops under `MQL_TESTER` (AU-14-03) -> tester behaviour
  is byte-identical.
- `ZeroMemory(st)` before `FileReadStruct` so a short/legacy file cannot
  leave stack garbage in the new field.
- At most 2 extra file writes per day.

## Acceptance
- Daily SL fires -> restart terminal -> halt still active, `Halted()` true,
  restore line in the journal.
- Halt expiry clears both `m_haltUntil` and `Cfg.HaltUntil`.
- Old BD15 state file -> defaults once, no crash, no garbage deadline.
- 4 new asserts on `MG_HaltDeadline`.
