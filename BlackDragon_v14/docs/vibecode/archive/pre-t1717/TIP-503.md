# TIP-503 — MobileControl scan reports transitions only

- Priority: P2
- Depends on: TIP-502 (shares Config.mqh)
- Finding: BD-R5

## Task
`CMobileControl::Scan` returned true on every scan while a matching
pending order existed, so a pending that could not be deleted (market
closed, trade context busy, broker refusal) made `OnTimer` call
`RedrawButtons()` + `Persist_Save()` twice a second and log forever.
Use the return value of `MC_Apply` (already pure and already reports real
flag changes): log + return true only on a transition. Add a
`BD_MC_DELETE_RETRY_SEC = 5` backoff on `m_nextDeleteTry` after a failed
`DeleteOrder`, with a throttled `Log_Warn("Mobile", "mcdel", ...)`.

## Constraints
- The command must STILL be re-applied every scan (MC_Apply is idempotent)
  so an undeletable pending keeps enforcing its state.
- Skipped in tester (`UseMobileControl && !MQL_TESTER`) — unchanged.

## Acceptance
- Undeletable pending: exactly one INFO line, one throttled WARN per 60 s,
  one delete attempt per 5 s, zero extra `Persist_Save()` calls.
- Normal path (delete succeeds): behaviour identical to v14.7.1.
- 4 new asserts (MC_Apply transition matrix).
