# TIP-507 — Re-arm the trail from the new breakeven after a DCA add (BD-R3)

- Priority: P1
- Depends on: —
- Finding: BD-R3 (`VERIFY_REPORT-v14.7.2.md`)
- Decision: Chu nha, 11/08/2026 — *"xoa SL nhung arm lai theo breakeven moi"*

## Task

A DCA add moves the breakeven, disarms the trail and (in `Trail_Mode = Real`)
sends `sl = 0`, removing the broker-side stop. That removal is **accepted**.
Two things must be true for it to be safe, and neither was:

1. **The re-arm must actually use the new breakeven.** `SeedExtreme()` threw
   away the tracked extreme on every `Rebuild()` — i.e. on every transaction
   on the symbol, including an SL/TP confirmation — and re-derived it from
   `CopyHigh`/`CopyLow` over *bars since the newest leg*. That window still
   contains the part of the current bar **before** the add, so a high printed
   while the basket had a higher breakeven could arm the trail instantly
   against the new, lower one. Virt mode: the basket closes on the spot. Real
   mode: a stop is pushed on the wrong side of price.
2. **The removal must be visible.** Nothing announced it.

Changes:

- `BasketManager.mqh`: the extreme becomes session state
  (`m_extremeBuy/Sell`) with an anchor (`m_anchorBuy/Sell` = openTime of the
  newest leg). It is monotonic across rebuilds and re-anchored **only** when a
  genuinely newer leg appears. `UpdateExtremes()` mirrors the live value back
  into the session copy.
- `Strategy.mqh`: when `RealLevels()` returns `sl = 0` while positions still
  carry a stop, log `Log_Warn("Strategy", "trailclr", ...)` once per side
  (60s throttle) naming the new breakeven.

## Constraints

- A leg being **removed** (overlap trim, partial close) must NOT re-derive the
  extreme — that would resurrect a pre-trim high. Keep the tracked value.
- On a fresh anchor, only bars that opened strictly **after** the leg's own bar
  may be read; the partial bar holding the add is covered by the live price
  plus `UpdateExtremes` from the next tick on. Under-arming is acceptable,
  over-arming is not.
- `iBarShift()` returning `-1` must be guarded — `iTime(..., -1)` is 0 and
  would seed `CopyHigh` from 1970.
- Restart recovery (C4's original purpose) must be preserved: after `OnInit`
  there is no session extreme, so bar history is read as before.
- `Cfg.TrailStart == 0` (default `iTS = 0`) → trail off, behaviour unchanged.
- Per-tick cost stays O(1); the `CopyHigh` path must not run every tick.

## Acceptance

- `iTS != 0`, buy basket armed, then force any unrelated transaction
  (SL/TP modify): the extreme must NOT drop back and the trail must stay armed.
- `iTS != 0`, buy basket in profit, then a DCA add: the trail must be disarmed
  and re-arm only after price exceeds `new breakeven + TrailStart`. It must not
  arm on the same tick as the add.
- Overlap trim on an armed basket: the extreme survives, no instant trail hit.
- `Trail_Mode = Real` + DCA add: exactly one `"trailclr"` warn per side per 60s,
  containing the new breakeven.
- Restart with an open, long-lived basket: the extreme is recovered from bar
  history as before.
